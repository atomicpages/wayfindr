# §7.11 `oauthserver`

Part of the [Wayfindr technical design](../design.md). Go code cites this file
as "design §7.11".

Wayfindr's own OAuth authorization server, for cloud agents that sign in with
OAuth instead of sending a header (ChatGPT; ADR 0022). Off unless
`[server.oauth] enabled`. This section is the contract the packages code
against: every exported name, signature, route, and JSON body below is fixed.
The ADR says why; the glossary has the terms (Wayfindr's authorization server,
allowed client, pending authorization, OAuth grant). The limits, the
`[server.oauth]` rules, and the store's rotation and pruning rules are stated
here only; other sections link here.

Until the public reference pages cover them (`docs/reference/http.md`,
`configuration.md`, and `cli.md`), this section also holds the routes, JSON
bodies, and messages users see. M3 moves those to the reference and links to
it from here.

Not to be confused with `internal/auth`, which is Wayfindr as an OAuth
_client_ of its connectors' authorization servers ([§7.3](7.3-auth.md)), or
with `/oauth/callback` (`auth.CallbackPath`), that client's redirect URI.

## The flow

```mermaid
sequenceDiagram
    autonumber
    participant C as ChatGPT (servers)
    participant B as User's browser
    participant T as Tunnel (public_url)
    participant H as httpd
    participant O as oauthserver
    participant U as webui (/ui, loopback)
    participant D as daemon (clientTokens)

    B->>U: POST /ui/cloud-agents/arm (Connect a client; session, CSRF)
    U->>D: admin POST /admin/oauth/arm
    D->>O: Server.Arm() → armed for 10 min
    U-->>B: "Ready for ChatGPT until hh:mm"
    C->>T: POST /mcp (no token)
    T->>H: forwarded, remote
    H-->>C: 401 WWW-Authenticate: Bearer resource_metadata="<issuer>/.well-known/oauth-protected-resource/mcp"
    C->>H: GET /.well-known/oauth-protected-resource/mcp (via T)
    H->>O: ResourceMetadata
    O-->>C: {resource: <issuer>/mcp, authorization_servers: [<issuer>]}
    C->>H: GET /.well-known/oauth-authorization-server (via T)
    O-->>C: {issuer, authorization_endpoint, token_endpoint, S256, CIMD, iss}
    C->>B: open <issuer>/oauth/authorize?client_id=…&redirect_uri=…&state=…&code_challenge=…&resource=…
    B->>H: GET /oauth/authorize (via T)
    H->>O: Authorize
    Note over O: client_id in clients? top-level navigation? armed? (else error page, no fetch)<br/>params, then fetch CIMD (public-only dialer, cached)<br/>redirect_uri listed? keep it pending (id, 10 min; at most 8 while armed)
    O-->>B: 302 http://<server.listen>/ui/oauth/approve?req=<id>
    B->>U: GET /ui/oauth/approve?req=<id> (loopback; no cookie yet: cross-site arrival)
    U-->>B: "Continue" page (claims nothing)
    B->>U: GET /ui/oauth/approve?req=<id> (Continue: same-site, console session)
    U->>D: admin GET /admin/oauth/requests/{id}
    D->>O: Server.Claim(id): consumes the arm, drops every other pending authorization
    U-->>B: approve page: client, redirect host, started, reported IP, warning, name, connectors
    B->>U: POST /ui/oauth/approve (same-origin, CSRF)
    U->>D: admin POST /admin/oauth/requests/{id}/approve {name, connectors}
    D->>O: Server.Approve(id, name, connectors)
    O->>D: Grants.CreateGrant (store row, shared name space)
    O-->>U: redirect_uri?code=…&state=…&iss=<issuer>
    U-->>B: 303 to redirect_uri
    B->>C: GET redirect_uri?code&state&iss
    C->>H: POST /oauth/token grant_type=authorization_code (via T)
    H->>O: Token: code, client_id, redirect_uri, code_verifier, resource
    O->>D: Grants.IssueGrantTokens(grant's CreatedAt, access 1h, refresh)
    D->>D: store + Registry.AddUntil(access digest, remote Client)
    O-->>C: {access_token, token_type: Bearer, expires_in: 3600, refresh_token}
    C->>H: POST /mcp Authorization: Bearer <access> (via T)
    H->>H: admitRemote: Registry.Lookup → Client{grant, connectors, Remote}
    H-->>C: MCP answer (narrowed to the grant's connectors)
    C->>H: POST /oauth/token grant_type=refresh_token (after 1h)
    O->>D: Grants.RotateGrantTokens(spent, new access, new refresh)
    O-->>C: new access and refresh tokens
```

## Limits

| What                                | Limit                                        | Where                          |
| ----------------------------------- | -------------------------------------------- | ------------------------------ |
| Access token                        | 1 hour                                       | `oauthserver.AccessTTL`        |
| Refresh token                       | no expiry; spent by its use                  |                                |
| Spent refresh token, kept for reuse | 30 days after it was spent                   | `store.OAuthSpentRetention`    |
| Code                                | 60 seconds; spent by its first presentation  | `oauthserver.CodeTTL`          |
| Spent code, remembered for reuse    | 10 minutes after it was spent                | `oauthserver.PendingTTL`       |
| Arm                                 | 10 minutes; one at a time; ended by a claim  | `PendingTTL`                   |
| Pending authorization               | 10 minutes; at most 8 while armed (the oldest goes), dropped when the arm ends; one claimed | `PendingTTL`, `MaxPending` |
| Spent refresh token, grace          | 30 seconds: refused without revoking         | `oauthserver.RefreshGrace`     |
| Grant approved, never exchanged     | pruned after 10 minutes                      | `store.OAuthUnexchangedTTL`    |
| CIMD document                       | 64 KiB, 5 seconds, no redirect               | `MaxDocument`, `FetchTimeout`  |
| CIMD cache                          | 1 hour when valid, 1 minute when failed      | `DocumentTTL`, `FailureTTL`    |
| Token request body                  | 16 KiB, read within 10 seconds               | `MaxTokenBody`, `TokenReadTimeout` |
| `state`                             | 2 KiB                                        |                                |
| Client name shown                   | 100 bytes, printable                         |                                |

## Configuration (`internal/config`)

`config.Server` gains one field, and `[server.oauth]` is its table:

```go
// OAuth is the [server.oauth] table: Wayfindr's authorization server
// (ADR 0022). A reload applies it.
type OAuth struct {
	// Enabled turns the authorization server on. It needs
	// Server.PublicURL.
	Enabled bool `toml:"enabled"`
	// Clients are the allowed clients: client IDs (CIMD URLs) matched
	// exactly. Absent means []string{DefaultOAuthClient}.
	Clients []string `toml:"clients"`
}

// DefaultOAuthClient is ChatGPT's client ID, the one allowed client when
// server.oauth.clients is absent.
const DefaultOAuthClient = "https://chatgpt.com/oauth/client.json"

type Server struct {
	Listen    string `toml:"listen"`
	PublicURL string `toml:"public_url"`
	OAuth     OAuth  `toml:"oauth"`
}

// Issuer is the authorization server's issuer: PublicURL in canonical form
// (scheme and host in lower case, no explicit :443, no trailing slash), ""
// when PublicURL is "". Every issuer, iss, resource, and metadata URL is
// built from it, so they agree byte for byte with the URI a client derives.
func (s Server) Issuer() string
```

- **Defaults.** `applyDefaults` sets `Clients` to `[]string{DefaultOAuthClient}`
  when `!md.IsDefined("server", "oauth", "clients")`. An explicit
  `clients = []` stays empty.
- **Validation** (`validator.oauth(Server)`, called from `config` after
  `publicURL`), all at load, reported with the rest:
  - `server.oauth.enabled` with `public_url` empty: `needs server.public_url`.
  - `server.oauth.clients` empty while `enabled`:
    `must list at least one client when server.oauth.enabled is true`.
  - Each entry, enabled or not, named by its 1-based position and never
    quoted: an absolute `https` URL with a host, a path other than `""` and
    `/`, no userinfo, no query (`?` anywhere, `ForceQuery` included), no
    fragment (`#` anywhere); in canonical form (`url.String()` returns the
    entry, the scheme and host are lowercase, and no path segment is `.` or
    `..`: `entry N is not in canonical form`); and no entry equal to an earlier
    one.
- **Diff.** `config.Diff` ignores `server.oauth`, as it ignores
  `public_url`: it is not in `RestartRequired`. The daemon applies it on every
  reload (see daemon below).
- **`SetPublicURL`** gains one refusal: clearing `public_url` while
  `server.oauth.enabled` is true is a `*ValidationError` at `server.public_url`,
  `is needed while server.oauth.enabled is true; turn it off first`, found
  before the file is edited (today a whole-config validation failure after the
  edit would read as `CaseUnparsable`).
- **Editor.** In `internal/config/edit_server.go`, modeled on `SetPublicURL`:

  ```go
  // SetOAuthEnabled returns src with server.oauth.enabled set to enabled,
  // and the configs before and after (ADR 0022). Only that line differs:
  // an existing key is rewritten on its line, keeping a comment after it;
  // a missing key goes after the last key of the [server.oauth] table; a
  // file with no [server.oauth] table gets one at its end, set off by a
  // blank line, holding only enabled = true. Setting false where the key
  // is absent changes nothing; setting false where it is present writes
  // enabled = false and keeps the table and its clients.
  //
  // Turning it on with no server.public_url is a *ValidationError at
  // server.oauth.enabled, and with an explicit empty clients list one at
  // server.oauth.clients (the validator's rules, found before the file is
  // edited). Otherwise it fails with an [*Error]: KindUnsafe
  // CaseUnparsable if src doesn't parse; CaseOAuthNotTable if server or
  // server.oauth is written as a dotted key or an inline table (oauth.enabled
  // = … inside [server], oauth = {…}, server.oauth.enabled = … at the top);
  // CaseMultiline if the value spans lines; CaseChangesOthers if the result
  // differs from src in anything but server.oauth.enabled. A UTF-8 byte order
  // mark is kept, as SetPublicURL keeps it.
  func SetOAuthEnabled(src []byte, enabled bool, opts Options) (Edited, error)
  ```

  `CaseOAuthNotTable Case = "oauth_not_table"` joins config's `unsafe` Cases.
  `setServerKey` becomes the shared
  `setTableKey(src []byte, table []string, notTable Case, key, text string) ([]byte, error)`.
  It refuses with `*Error{Kind: KindUnsafe, Case: notTable, Key: <prefix>}`, Key
being the prefix that is not a table (`server` or `server.oauth`, which the
reason names), whenever the table
  can't be given a header of its own: the table, or any prefix of it, written as
  a dotted key or an inline table. `SetPublicURL` passes `[]string{"server"}`
  and `CaseServerNotTable`, as today; `SetOAuthEnabled` passes
  `[]string{"server", "oauth"}` and `CaseOAuthNotTable`, so a dotted or inline
  `server` is `oauth_not_table` there too. The console only toggles `enabled`;
  nothing edits `clients`.

## Store (`internal/store`, both drivers)

Migrations: SQLite `0008_oauth.sql`, Postgres `0012_oauth.sql`. Additive only
(two new tables), so a rollback leaves them unused. The tables are in
[§5](5-data-model.md). Row types in `store.go`:

```go
// ErrSpent is returned by RotateOAuthTokens when the refresh token was
// already spent: a reuse, which revokes the grant (ADR 0022).
var ErrSpent = errors.New("already spent")

const (
	// OAuthSpentRetention is how long a spent refresh token is kept, so
	// that presenting it again is seen as a reuse.
	OAuthSpentRetention = 30 * 24 * time.Hour
	// OAuthUnexchangedTTL is how long a grant with no token (approved, its
	// code never exchanged) is kept.
	OAuthUnexchangedTTL = 10 * time.Minute
)

// OAuthGrant is an OAuth grant (GLOSSARY): an allowed client's access,
// approved in the console, to its connectors. Its name is in the name
// space ClientToken names are in.
type OAuthGrant struct {
	UserID string
	Name   string
	// ClientID is the allowed client's CIMD URL.
	ClientID string
	// Resource is <public_url>/mcp when the grant was approved (RFC 8707).
	Resource string
	// Connectors are the connectors the grant may use; at least one.
	Connectors []string
	CreatedAt  time.Time
	// LastUsedAt is when its access token was last used, as
	// TouchOAuthGrants recorded it; nil until first use.
	LastUsedAt *time.Time
}

// OAuthTokenKind is what an OAuthToken is.
type OAuthTokenKind string

const (
	OAuthAccess  OAuthTokenKind = "access"
	OAuthRefresh OAuthTokenKind = "refresh"
)

// OAuthToken is one access or refresh token of a grant. Only its SHA-256
// is stored (clienttoken.Digest).
type OAuthToken struct {
	UserID string
	Digest [sha256.Size]byte
	// Grant is the grant's name.
	Grant     string
	Kind      OAuthTokenKind
	CreatedAt time.Time
	// ExpiresAt is set for an access token, nil for a refresh token.
	ExpiresAt *time.Time
	// UsedAt is when a refresh token was spent; nil until then, and always
	// nil for an access token.
	UsedAt *time.Time
}
```

`Store` gains these methods, after the client tokens. Every time is kept to the
millisecond; each takes the user ID as the existing methods do.

```go
// CreateOAuthGrant stores g. It fails with an error wrapping ErrExists
// when the user has an OAuth grant or a scoped client token of that name,
// and refuses an empty Connectors, ClientID, or Resource, or a zero
// CreatedAt. LastUsedAt is ignored.
CreateOAuthGrant(ctx context.Context, g OAuthGrant) error
// GetOAuthGrant returns the grant called name, or ErrNotFound.
GetOAuthGrant(ctx context.Context, userID, name string) (OAuthGrant, error)
// ListOAuthGrants returns the user's grants, ordered by name.
ListOAuthGrants(ctx context.Context, userID string) ([]OAuthGrant, error)
// DeleteOAuthGrant removes the grant and, by cascade, its tokens, or
// returns ErrNotFound.
DeleteOAuthGrant(ctx context.Context, userID, name string) error
// GetOAuthToken returns the user's token with digest d, or ErrNotFound.
GetOAuthToken(ctx context.Context, userID string, d [sha256.Size]byte) (OAuthToken, error)
// ListOAuthAccessTokens returns the user's access tokens that expire after
// now, ordered by grant name.
ListOAuthAccessTokens(ctx context.Context, userID string, now time.Time) ([]OAuthToken, error)
// IssueOAuthTokens stores a grant's first access and refresh tokens in one
// transaction (a code exchange). Both must name the same grant, which must
// exist (else ErrNotFound) and have no token yet (else ErrExists); access
// must be OAuthAccess with ExpiresAt, refresh OAuthRefresh without, and
// neither UsedAt. It also refuses a zero CreatedAt, an empty Grant, equal
// digests, and a token whose UserID is neither empty nor userID
// (CheckOAuthTokenPair).
IssueOAuthTokens(ctx context.Context, userID string, access, refresh OAuthToken) error
// RotateOAuthTokens spends the refresh token spent and stores its
// successors, in one transaction: it sets spent's UsedAt to at only if it
// is unset (one conditional UPDATE, so two racing rotations can't both
// win), deletes the grant's access tokens, and inserts access and refresh,
// which must name spent's grant. Spent refresh tokens stay (PruneOAuth
// drops them after OAuthSpentRetention). A spent token already spent is
// ErrSpent and changes nothing; no refresh token with that digest, or no
// grant named by access, is ErrNotFound. A failed rotation leaves spent
// unspent. It refuses what IssueOAuthTokens refuses, and a zero at
// (CheckOAuthRotation). Postgres locks the grant's row before the token's, the
// order DeleteOAuthGrant takes them in, so a rotation racing the grant's
// delete ends in ErrNotFound, never a deadlock.
RotateOAuthTokens(ctx context.Context, userID string, spent [sha256.Size]byte, at time.Time, access, refresh OAuthToken) error
// TouchOAuthGrants records, for each digest that is one of the user's
// access tokens, that its grant was last used at that time, in one
// transaction. LastUsedAt never moves backwards; other digests (client
// tokens, revoked grants) are ignored. The daemon passes it the same map
// as TouchClientTokens.
TouchOAuthGrants(ctx context.Context, userID string, used map[[sha256.Size]byte]time.Time) error
// PruneOAuth deletes the user's access tokens that expired at or before
// now, the refresh tokens spent at or before now minus
// OAuthSpentRetention, and the grants that have no token and were created
// at or before now minus OAuthUnexchangedTTL (approved, never exchanged),
// and returns how many rows it deleted.
PruneOAuth(ctx context.Context, userID string, now time.Time) (int64, error)
```

`CreateClientToken` also refuses, with `ErrExists`, a name an OAuth grant has.
Both checks run in the insert's transaction. `storetest` covers all of it on
both drivers, including the cascade, the shared name space, two racing
rotations of one refresh token, and a rotation racing the delete of its grant.

The refusals made before the database is touched are three exported functions
in `store/oauth.go`, which both drivers call so they refuse the same inputs:

```go
// CheckOAuthGrant reports why CreateOAuthGrant must refuse g: no
// Connectors, ClientID, or Resource, or a zero CreatedAt.
func CheckOAuthGrant(g OAuthGrant) error
// CheckOAuthTokenPair reports why IssueOAuthTokens or RotateOAuthTokens must
// refuse access and refresh: the wrong Kinds, an access token with no
// ExpiresAt or a refresh token with one, a UsedAt on either, a zero
// CreatedAt, an empty Grant or two different grants, equal digests, or a
// UserID that is neither empty nor userID.
func CheckOAuthTokenPair(userID string, access, refresh OAuthToken) error
// CheckOAuthRotation is CheckOAuthTokenPair plus a refusal of a zero at.
func CheckOAuthRotation(userID string, at time.Time, access, refresh OAuthToken) error
```

## Token plumbing (`internal/clienttoken`)

```go
// AddUntil registers c under digest d, as Add does, until expires. From
// then on Lookup misses d: it drops the entry, as Remove would, and records
// no touch. Add of the same digest or name later replaces the entry and
// its expiry.
func (r *Registry) AddUntil(d [sha256.Size]byte, c Client, expires time.Time)
```

`Lookup` compares with the registry's `now`: an entry expires when
`!now().Before(expires)`. Add, Remove, Touches, and the one-to-one name ↔
digest rule are unchanged, so a grant has at most one live access token in the
registry: a rotation's `AddUntil` under the grant's name replaces the last one.
An entry never looked up again stays until its grant is revoked, rotated, or
the daemon restarts: at most one per grant.

A grant's access token resolves to
`clienttoken.Client{Name: g.Name, Connectors: g.Connectors, Remote: true}`. So
httpd's `resolveBearer` and `admitRemote` let it through to `/mcp` as a remote
scoped token, with no new guard logic, and the admin API refuses it with 403.
Access and refresh token values are `clienttoken.Generate()`: `wf_s_` and the
base64url of 32 random bytes. No new prefix.

## Public-only dialer (`internal/httpclient`)

```go
// ErrNotPublic is what a dial made by PublicOnly's client fails with when
// the address it connects to is not public.
var ErrNotPublic = errors.New("address is not public")

// PublicOnly returns an HTTP client for fetching a URL a stranger may name.
// Its transport is a clone of the default one with no proxy (a proxy's
// address would be the one checked), and its dialer's Control refuses,
// with an error wrapping ErrNotPublic, any address that, unmapped from
// IPv4-in-IPv6, is not global unicast (loopback, link-local, multicast,
// unspecified), is private (RFC 1918, fc00::/7), or is in a refused range:
// 100.64.0.0/10 (shared), 0.0.0.0/8, 192.0.0.0/24, 192.88.99.0/24 (6to4
// relay), 198.18.0.0/15, 240.0.0.0/4 (which holds 255.255.255.255),
// ::/96 (IPv4-compatible), ::ffff:0:0:0/96 (SIIT IPv4-translated),
// 100::/64 (discard), 2001::/32 (Teredo),
// fec0::/10 (site-local), 64:ff9b::/96 and 64:ff9b:1::/48 (NAT64), or
// 2002::/16 (6to4); the translation and tunnel ranges because they embed an
// IPv4 address that may be any of the above. Control runs on the resolved address of every connection attempt, so
// a name that resolves, or rebinds, to such an address is refused at
// connect time. The client follows redirects as the default does and has
// no Timeout: callers set CheckRedirect on a copy and bound each request
// with its context.
func PublicOnly() *http.Client
```

It stays in `httpclient`, which imports only the standard library and
`config`, so the fix for wayfindr-pgj8 (discovery endpoints on private hosts)
can reuse the same Control later. `oauthserver` gets it from `daemon` through
`Options.Client`; tests pass their own client.

## Package `oauthserver`

`internal/oauthserver` sits in the middle row beside `auth`. It imports `store`
(row types, `ErrNotFound`, `ErrExists`, `ErrSpent`), `config` (`config.Server`),
`clienttoken` (`Generate`, `Digest`), `redact` (`Printable`), and `httpclient`
(`ErrNotPublic`, to name that failure in its log line; the client itself is
injected). It never imports `httpd`, `auth`, `daemon`, `webui`, or `admin`.
Writes to the store and the registry go up through the `Grants` interface, which
`daemon` implements; the running config comes through a function.

### Constants and helpers

```go
const (
	AccessTTL        = time.Hour        // access token lifetime
	CodeTTL          = 60 * time.Second // authorization code lifetime; single use
	PendingTTL       = 10 * time.Minute // how long an arm, and a pending authorization, lasts
	RefreshGrace     = 30 * time.Second // a refresh token spent this recently is refused, not revoked
	MaxDocument      = 64 << 10         // CIMD body cap, bytes
	FetchTimeout     = 5 * time.Second  // one CIMD fetch
	DocumentTTL      = time.Hour        // a fetched, valid CIMD document is reused this long
	FailureTTL       = time.Minute      // a failed fetch is remembered this long
	MaxTokenBody     = 16 << 10         // token request body cap, bytes
	TokenReadTimeout = 10 * time.Second // reading one token request's body
	MaxPending       = 8                // pending authorizations kept while armed; past it the oldest goes
)

const (
	ResourceMetadataPath = "/.well-known/oauth-protected-resource"
	ServerMetadataPath   = "/.well-known/oauth-authorization-server"
	AuthorizePath        = "/oauth/authorize"
	TokenPath            = "/oauth/token"
)

// Resource is the resource every grant is bound to: issuer + "/mcp".
func Resource(issuer string) string

// ResourceMetadataURL is the URL a 401 challenge names:
// issuer + ResourceMetadataPath + "/mcp" (RFC 9728 §3.1).
func ResourceMetadataURL(issuer string) string

// ErrSuspended is what Grants' issue and rotate return for a suspended
// grant: the authorization server is off, public_url changed since the
// grant was approved (its Resource is not the current one), or its client
// is no longer in server.oauth.clients. Undoing the change lifts it.
var ErrSuspended = errors.New("the grant is suspended")

// ErrNoRequest means a pending authorization id that is unknown, expired,
// not claimed, already answered, or no longer current (its resource
// changed, its client is no longer allowed, or the daemon disarmed the
// server).
var ErrNoRequest = errors.New("no such pending authorization")

// ErrContested is what Approve returns when more than one authorization
// request became pending during the arm the claimed request came from
// (Request.Arrived): one may be a stranger's, so none is approved. Deny
// still answers the request; the user arms again and retries.
var ErrContested = errors.New("more than one authorization request arrived during the arm")

// ErrInvalidName is what Grants.CreateGrant wraps for a name a client token
// could not have: not a connector name, or the default token's. The admin
// API checks the name before Approve, so this is its 400 should a name get
// past that check.
var ErrInvalidName = errors.New("invalid grant name")
```

These four stay plain sentinels, an exception to CODING_STANDARDS' seam-error
rule (`*Error{Kind, Case}` for a seam callers branch on), as `store`'s
`ErrNotFound` and `ErrExists` are: each has one meaning and one mapping (the
daemon's admin adapter turns `ErrNoRequest` into `store.ErrNotFound`, a 404,
`ErrInvalidName` into a 400, and `ErrContested` into `admin.ErrContested`, a
409; the token endpoint turns `ErrSuspended` into
`invalid_grant`), so a Kind and Case would add nothing.

### Construction

```go
// Grants is what the authorization server needs of the daemon's token
// service. The daemon's clientTokens implements it under the one lock it
// holds for client tokens, so grants and client tokens share one name
// space. UserID on every row passed in is ignored: the daemon sets its
// user.
type Grants interface {
	// CreateGrant stores g. A taken name, by a grant or a client token, is
	// an error wrapping store.ErrExists; a name a client token could not
	// have, one wrapping ErrInvalidName.
	CreateGrant(ctx context.Context, g store.OAuthGrant) error
	// Grant returns the grant called name, or store.ErrNotFound.
	Grant(ctx context.Context, name string) (store.OAuthGrant, error)
	// GrantToken returns the stored token with digest d, or
	// store.ErrNotFound.
	GrantToken(ctx context.Context, d [sha256.Size]byte) (store.OAuthToken, error)
	// IssueGrantTokens stores a grant's first tokens and starts accepting
	// access until its ExpiresAt: store.IssueOAuthTokens, then
	// Registry.AddUntil. created is the CreatedAt of the grant the code
	// was made for, compared to the millisecond (as the store keeps it):
	// a grant re-created under the same name since is another grant, and
	// gets no tokens. store.ErrNotFound when the grant is gone or was
	// re-created; ErrSuspended when it is suspended.
	IssueGrantTokens(ctx context.Context, created time.Time, access, refresh store.OAuthToken) error
	// RotateGrantTokens spends refresh token spent and stores and accepts
	// its successors: store.RotateOAuthTokens, then Registry.AddUntil,
	// which replaces the grant's previous access token. store.ErrSpent,
	// store.ErrNotFound, and ErrSuspended as there.
	RotateGrantTokens(ctx context.Context, spent [sha256.Size]byte, access, refresh store.OAuthToken) error
	// RevokeGrant deletes the grant called name with its tokens and stops
	// accepting its access token. It never deletes a client token.
	// store.ErrNotFound when there is no such grant.
	RevokeGrant(ctx context.Context, name string) error
}

// Options is what New needs. The daemon builds it once.
type Options struct {
	// Server returns the running config's [server] table, read on every
	// request.
	Server func() config.Server
	Grants Grants
	// ApproveURL returns the console's approve page for pending authorization
	// id, on the daemon's loopback address.
	ApproveURL func(id string) string
	// Client fetches CIMD documents. The daemon passes
	// httpclient.PublicOnly(); New uses a copy that follows no redirect.
	// Nil means httpclient.PublicOnly().
	Client *http.Client
	// FetchTimeout bounds one CIMD fetch, through its request's context;
	// zero means FetchTimeout. Tests shorten it.
	FetchTimeout time.Duration
	// Now is the clock; nil means time.Now.
	Now    func() time.Time
	Logger zerolog.Logger
}

// Server is the authorization server: its four HTTP handlers, the pending
// authorizations, and the codes. Safe for concurrent use.
func New(opts Options) *Server
```

"On" below means `Server().OAuth.Enabled`; the issuer is `Server().Issuer()`,
which validation makes non-empty whenever it is on. Pending authorizations
(the unclaimed ones and the claimed one), codes, spent codes' digests, and the
CIMD cache live in memory, behind one mutex, and are lost on restart. A pending
authorization is a `Request` in Go.

### HTTP handlers

Four methods with the `http.HandlerFunc` signature, wired by `daemon` into
`httpd.Handlers`. Each answers `http.NotFound` (`404 page not found`) while
off, so a local request then gets what a remote one does.

```go
func (s *Server) ResourceMetadata(w http.ResponseWriter, r *http.Request)
func (s *Server) ServerMetadata(w http.ResponseWriter, r *http.Request)
func (s *Server) Authorize(w http.ResponseWriter, r *http.Request)
func (s *Server) Token(w http.ResponseWriter, r *http.Request)
```

**`ResourceMetadata`** serves both `ResourceMetadataPath` and
`ResourceMetadataPath + "/mcp"` with `200`, `Content-Type: application/json`,
`Cache-Control: no-cache`:

```json
{
  "resource": "https://w.example/mcp",
  "authorization_servers": ["https://w.example"],
  "bearer_methods_supported": ["header"],
  "resource_name": "Wayfindr"
}
```

**`ServerMetadata`** (RFC 8414), same headers. No `scopes_supported` and no
`registration_endpoint`:

```json
{
  "issuer": "https://w.example",
  "authorization_endpoint": "https://w.example/oauth/authorize",
  "token_endpoint": "https://w.example/oauth/token",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "code_challenge_methods_supported": ["S256"],
  "token_endpoint_auth_methods_supported": ["none"],
  "client_id_metadata_document_supported": true,
  "authorization_response_iss_parameter_supported": true
}
```

**Arming.** The server accepts an authorization only while it is _armed_,
and only the console arms it: the user chooses Connect (a session and CSRF
form, `POST /admin/oauth/arm`), which calls

```go
// Arm lets authorization requests through for PendingTTL from now, and
// returns when the arm ends. There is one arm at a time: arming again
// resets the expiry, and keeps the pending authorizations and their count.
// While armed, every authorize request that passes every check through
// step 10 becomes a pending authorization (at most MaxPending; past it the
// oldest goes) and is counted (Request.Arrived). The arm ends when the
// console claims one of them (Claim) or when it expires, and then the
// unclaimed ones are dropped.
func (s *Server) Arm() (expires time.Time)

// Disarm ends the arm and drops every pending authorization, the claimed
// request, and every authorization code not yet presented. The daemon
// calls it when a reload turns the server off, changes the resource
// (public_url), or changes the allowed clients, so nothing armed or
// claimed under the old settings is answered under the new ones: the user
// selects Connect a client again.
func (s *Server) Disarm()
```

Authorize never consumes the arm; the console does, when the user's signed-in
browser opens the approve page (`Claim`, below). So a stranger can't create a
pending authorization except in the minutes after the user chose Connect, and
can't keep the user's out: the client ID and the `redirect_uri` are public (the
CIMD document lists it), so anyone can send a valid authorize request, but
while armed the stranger's requests only sit beside the user's. Only a request
id that reaches the user's own console, by the user's own browser following the
`302`, gets claimed, and the claim drops every other pending authorization, so
a stranger's request can never be approved after it. Arming again (`Arm`
sweeps first) starts with none of the last arm's unclaimed requests. Refreshes
never touch authorize, so an arm is needed only to connect.

**One request per arm.** The server counts the authorization requests that
became pending during the current arm (step 12), evicted ones included; a new
arm, one that starts after the last has ended, counts from zero, while arming
again within an arm keeps the count with the requests. `Claim` copies the count
into the claimed request (`Request.Arrived`). Only the user's own request is
expected, so when more than one arrived the claimed one may be a stranger's: a
page the user has open can open
`http://127.0.0.1:<port>/ui/oauth/approve?req=<the stranger's id>` in a new tab
while the user is armed, and the user, expecting the approve page, selects
Continue just as in the real flow. So `Approve` fails closed: with
`Arrived > 1` it returns `ErrContested` and changes nothing; the request stays
claimed, `Deny` answers it, and the user arms again and retries. A stranger's
request then costs the user a retry, never a grant. What is left is a
stranger's request that is the only one in the arm (the user's own never
arrives before the claim) and that the user approves although the page names
the client, its start time, and the reported IP.

**Disarm.** The daemon calls `Disarm` from `Reload` whenever the server turns
off or on, the resource changes (`public_url`), or `server.oauth.clients`
changes. It ends the arm, drops the pending authorizations and the claimed
request, and forgets every code not yet exchanged. Without it, turning sign-in
off and on again within `PendingTTL` would bring a claim and an arm back, since
neither the resource nor the expiry changed. `Approve` also answers
`ErrNoRequest` when the claimed request's client is no longer in
`server.oauth.clients`, for a reload that lands between the check and the
grant.

The cap bounds memory, not the stranger: one who sends more than `MaxPending`
valid requests in the seconds between the user's `302` and the click on
Continue evicts the user's, whose approve page then says the request expired;
the user starts again in the client. That costs availability for as long as the
flood lasts, never a grant.

**`Authorize`** (`GET` only) checks, in this order, and stops at the first
failure. Until step 10 passes the `redirect_uri` is not trusted, so every
failure through step 10 is the **error page** and never a redirect:

1. Exactly one `client_id` parameter, and it is in
   `Server().OAuth.Clients`, compared exactly (`client_not_allowed`). This
   comes before anything else, so a missing, repeated, or unknown
   `client_id` gets this page and nothing more: no fetch, no pending
   authorization, no log line beyond a debug one.
2. Only a top-level page the user opens passes (`not_navigation`), local or
   remote. A request with any `Sec-Fetch-*` header must have
   `Sec-Fetch-Mode: navigate` and `Sec-Fetch-Dest: document`, whatever its
   `Sec-Fetch-Site`, so neither a web page's `no-cors` request nor a page
   framed in a hidden iframe passes. A request whose `Sec-Purpose` or older
   `Purpose` contains `prefetch` or `prerender` (case-insensitive) is refused
   too: a speculative load is not the user opening the page. A request
   without any of these headers (a non-browser client) passes.
3. The server is armed (`not_armed`: "Wayfindr isn't expecting a connection.
   Open Wayfindr's console, choose Connect, then try again in the app."). This
   only reads the arm.
4. No other parameter given twice (`duplicate_parameter`).
5. `response_type` is `code` (`unsupported_response_type`).
6. `code_challenge_method` is `S256` and `code_challenge` is exactly 43
   base64url characters, an S256 digest's length (`invalid_pkce`).
7. `resource` equals `Resource(issuer)` exactly (`invalid_resource`).
8. `state` is present, at most 2 KiB (`missing_state`).
9. `redirect_uri` is an absolute `https` URL, or `http` on `127.0.0.1`,
   `[::1]`, or `localhost`, with no fragment (`invalid_redirect_uri`).
10. The client's CIMD document (below) is valid and lists `redirect_uri`
    exactly in `redirect_uris` (`client_document`, `redirect_not_registered`).

`scope` is ignored. Then, under the server mutex:

11. Still armed; if a claim or the expiry ended the arm meanwhile,
    `not_armed`. The arm is only read: authorize never consumes it.
12. Keep the new pending authorization beside the others, dropping the oldest
    when there are already `MaxPending`: an id from `rand.Text()`
    (`crypto/rand`, 128 bits), the client ID, its name and host,
    `redirect_uri`, `state`, `code_challenge`, the resource, `StartedAt` (now),
    the reported IP (below), and `PendingTTL`, and add one to the arm's count
    (One request per arm, above). Answer `302` to `ApproveURL(id)`.

The **reported IP** is the address the tunnel says the browser came from: the
last entry of the last `X-Forwarded-For` header, kept only if it parses as an
IP address with no zone (`netip.ParseAddr`); otherwise none. A proxy appends the
address it saw to `X-Forwarded-For`, so the last entry is the nearest proxy's
and the ones before it are whatever the browser sent. No vendor header counts:
a browser can send `CF-Connecting-IP` and `Cf-Ray` itself, and a tunnel that is
not Cloudflare's passes them on, so neither, alone or together, says anything
the tunnel vouched for. (Cloudflare's tunnel sets `X-Forwarded-For` too.) A
tunnel that passes a browser's `X-Forwarded-For` on without appending can still
be fooled, which is why the IP is shown on the approve page as "reported by your
tunnel" and never trusted for any decision.

Every redirect this server sends (the URLs Approve and Deny return) appends its
parameters to `redirect_uri`'s own query (RFC 6749 §3.1.2) and carries
`iss=<issuer>` (RFC 9207). The `302` to the approve page sets
`Cache-Control: no-store` and `Referrer-Policy: no-referrer`.

The **error page** is a small embedded `html/template` page, status 400: one
fixed sentence per case above (closed set; tests match the case, which the page
carries in a `data-case` attribute), "Close this page and start connecting
again", and nothing taken from the request. Headers:
`Content-Type: text/html; charset=utf-8`,
`Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`,
`Cache-Control: no-store`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`.

**CIMD document.** Fetched with `GET` and `Accept: application/json` through
`Options.Client` (a copy whose `CheckRedirect` returns
`http.ErrUseLastResponse`, and whose `Timeout` is left as the base client's:
`PublicOnly` sets none), bounded by `Options.FetchTimeout` (`FetchTimeout`
when zero) through the request's context. It fails unless the
answer is `200`, at most `MaxDocument` bytes (`MaxDocument+1` are read; more is
a failure), and one JSON object in which:

- `client_id` equals the URL fetched;
- `redirect_uris` is a non-empty array of strings;
- `token_endpoint_auth_method` (string) and
  `token_endpoint_auth_methods_supported` (array; SEP-3149), if either is
  present, include `none` between them;
- `client_name`, if present, is a string. It is shown through
  `redact.Printable`, clipped to 100 bytes; when absent the client host
  stands in.

A valid document is cached per client ID for `DocumentTTL`, a failure for
`FailureTTL`. A fetch runs outside the server mutex: at most one fetch per
client ID is in flight (`golang.org/x/sync/singleflight`, keyed by the client
ID), and other requests for the same client wait for its result, so a slow
fetch never holds up the pending authorization, the codes, or the token
endpoint. The fetch runs under the context of the request that started it
without its cancellation: a caller that goes away gets `client_document`
at once, while the fetch goes on and fills the cache for the others. Only allowed client IDs are fetched, so the cache holds at most
`len(clients)` entries. A failure is logged at warn with the client host and
the reason (status, size, timeout, `ErrNotPublic`), never the body.

**`Token`** (`POST` only). Body `application/x-www-form-urlencoded`, at most
`MaxTokenBody` (`http.MaxBytesReader`), read within `TokenReadTimeout` of wall
time (`http.NewResponseController(w).SetReadDeadline`; a writer that can't set
one, `http.ErrNotSupported`, reads without it), so a body sent a byte at a time
can't hold a connection open. Every answer is JSON with `Cache-Control: no-store` and
`Pragma: no-cache`. A success is `200`:

```json
{
  "access_token": "wf_s_…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "wf_s_…"
}
```

An error is `{"error": "<code>", "error_description": "<fixed sentence>"}`,
status 400 except `invalid_client` (401, with `WWW-Authenticate: Basic` only
when the request had an `Authorization` header). Inputs are never echoed. In
order:

1. A malformed or oversized body, or a parameter given twice:
   `invalid_request`.
2. Any client authentication (an `Authorization` header, `client_secret`,
   `client_assertion`, or `client_assertion_type`): `invalid_client`.
3. `client_id` missing: `invalid_request`; not in `Server().OAuth.Clients`:
   `invalid_client` (removing a client from `clients` stops its refreshes).
4. `grant_type` `authorization_code` or `refresh_token`, else
   `unsupported_grant_type`.

`authorization_code` (`code`, `redirect_uri`, `code_verifier` required, else
`invalid_request`):

- A code is `rand.Text()` (`crypto/rand`, 128 bits), as the pending id is.
  Codes are kept in memory by their SHA-256. An unknown code, or one not
  presented within `CodeTTL`, is `invalid_grant`. A code is spent by its
  first presentation, whatever the outcome, and its digest is then
  remembered for `PendingTTL`. Presented again within that window, it
  revokes its grant (`Grant`, and if its `CreatedAt` is the one the code
  recorded, `RevokeGrant`, so a grant re-created under the same name is
  never hit) and is `invalid_grant`; after the window it is an unknown code.
  The code records its grant's `CreatedAt` truncated to the millisecond, as
  the store keeps it.
- `client_id` and `redirect_uri` must equal the code's; the verifier must be
  43 to 128 unreserved characters and its S256 must equal the challenge
  (constant time). Any mismatch: `invalid_grant`.
- `resource`, when sent, must equal the code's: else `invalid_target`. The
  code's resource must be `Resource(issuer)`: else `invalid_grant`.
- Two `clienttoken.Generate()` values; `IssueGrantTokens` with the code's
  grant `CreatedAt` and the access token expiring at `now + AccessTTL`.
  `ErrSuspended` or `store.ErrNotFound` (revoked meanwhile, or revoked and
  re-created under the same name within `CodeTTL`): `invalid_grant`, and
  nothing is issued. Another error: 500 `server_error`, logged.

`refresh_token` (`refresh_token` required):

- `GrantToken(digest)`: unknown, or not a refresh token, is `invalid_grant`.
  Already spent (`UsedAt` set): `invalid_grant`, and the grant is revoked
  unless it was spent less than `RefreshGrace` ago: `Grant`, and if its
  `CreatedAt` is not after the spent token's (both to the millisecond),
  `RevokeGrant`, so a grant revoked and re-created under the same name after
  the token was read is never hit, as for a replayed code.
- `Grant(name)`: gone is `invalid_grant`. `client_id` must equal its
  `ClientID` (`invalid_grant`); `resource`, when sent, its `Resource`
  (`invalid_target`); its `Resource` must be `Resource(issuer)`
  (`invalid_grant`: a changed `public_url` suspends the grant until it is set
  back).
- `RotateGrantTokens` with two new values. `store.ErrSpent` (a rotation that
  raced this one and won, so spent within `RefreshGrace`): `invalid_grant`,
  nothing revoked. `store.ErrNotFound` or `ErrSuspended`: `invalid_grant`.

The two revokes a reuse causes (a replayed code; a refresh token presented
after the grace) run under `context.WithTimeout(context.WithoutCancel(ctx),
5s)`: a client that disconnects once it has presented the stolen value can't
call the revoke off.

A spent refresh token stays in the store for `store.OAuthSpentRetention`.
Presented again within `RefreshGrace` of its spend, it is refused without
revoking: a client whose workers refresh concurrently, or that retries a
refresh whose answer it lost, keeps its grant. Presented later, within the
retention, it revokes the grant; after the retention it is unknown
(`invalid_grant`) and nothing is revoked. The trade-off: a thief who refreshes
first, followed by the real client within 30 seconds, is not caught then; the
real client is refused, and its next attempt with that token, after the grace,
revokes the grant.

Logs: info for an arm, an approve, a deny, an issue, and a rotation, with the
grant name and client host; warn for a revoke on reuse; debug for every
refused token request (its error code and grant type, nothing else) and every
error page (its case). Never a code, token, verifier, challenge, or `state`,
and never a query string. A remote `/mcp` refusal is httpd's, logged at debug
(see httpd below).

### The console's side

```go
// Request is a pending authorization (GLOSSARY) as the approve page
// shows it.
type Request struct {
	ID           string
	ClientID     string
	ClientName   string // printable, at most 100 bytes; the host when the document has none
	ClientHost   string // client_id's host[:port]
	RedirectHost string // redirect_uri's host[:port]
	StartedAt    time.Time
	// ReportedIP is the browser's address as the tunnel reported it (the
	// last X-Forwarded-For entry); "" when none. Shown, never trusted.
	ReportedIP string
	ExpiresAt  time.Time
	// Arrived is how many authorization requests became pending during
	// the arm this one was claimed from, this one included, counted when
	// it was claimed; zero until then. Only one was expected: above one,
	// Approve refuses with ErrContested.
	Arrived int
}

// Claim is the console's signed-in GET of the approve page for pending
// authorization id. While armed, claiming one of the pending
// authorizations consumes the arm, drops every other pending
// authorization, and returns the request, with Arrived set to how many
// became pending during the arm: from then on it is the only one
// Approve and Deny answer, and authorize says not_armed until the next
// Arm. Claiming the claimed request again (a reload) returns it with no
// other effect. False, with no effect, when id is not pending, the arm has
// ended, or the request is no longer current; and for any other id once
// one is claimed, unless the server was armed again and id is one of the
// new pending authorizations, which then replaces the claimed one.
func (s *Server) Claim(id string) (Request, bool)

// Pending returns the claimed request if its id is id, with no effect:
// what Claim returns on a reload. False when id is unknown, not claimed
// (a request that is only pending reads false), expired, answered, or no
// longer current.
func (s *Server) Pending(id string) (Request, bool)

// Approve creates the grant name for connectors (Grants.CreateGrant, with
// the request's client ID and resource, CreatedAt now), makes a code bound
// to it (CodeTTL, single use), and returns redirect_uri with code, state,
// and iss. Only the claimed request is answered: ErrNoRequest when Pending
// would say false, which it does for a request that is pending but not
// claimed. A CreateGrant error (a taken name: store.ErrExists) is returned
// as is, and the request stays claimed so the user can pick another name.
// A request is answered at most once: of two racing Approves, one gets
// ErrNoRequest. ErrNoRequest too when the request's client is no longer
// in server.oauth.clients.
//
// ErrContested, with no effect, when more than one authorization request
// became pending during the arm the request was claimed from
// (Request.Arrived): only the user's own was expected, so the one claimed
// may be a stranger's, opened in a tab the user didn't open. The request
// stays claimed, so Deny still answers it.
func (s *Server) Approve(ctx context.Context, id, name string, connectors []string) (redirect string, err error)

// Deny ends the claimed request and returns redirect_uri with
// error=access_denied, state, and iss. ErrNoRequest as for Approve.
func (s *Server) Deny(id string) (redirect string, err error)
```

Only the console calls `Claim`, through the admin API's `GET
/admin/oauth/requests/{id}`, and only for a signed-in `GET` of the approve
page; the page a browser without a session gets (the "Continue" page, §7.10)
claims nothing. The console cookie is `SameSite=Strict`, so a page on another
site that navigates the user's browser to the approve page with a stranger's
id gets the Continue page, not a claim. The user's click on Continue, a
same-origin navigation, does claim it: the Continue page looks the same
whether the user's client or a page the user has open opened the tab, which is
why it says to continue only after selecting Connect in an app, and why
`Approve` refuses a request that was not alone in its arm (One request per
arm, above). Constant time: `Claim` compares the id
with every pending authorization's, and `Pending`, `Approve`, and `Deny` with
the claimed one's, by `subtle.ConstantTimeCompare`.

`Approve` takes the claimed request out, under the server mutex, before it
calls `CreateGrant` (which writes the store, outside the mutex), and puts it
back only if `CreateGrant` fails and no newer claim has replaced it meanwhile.
So while the grant is being stored `Pending` reads false, and a racing
`Approve` or `Deny` gets `ErrNoRequest`; of any two racing answers exactly one
wins.

The name and connectors are checked by `admin` before `Approve` (the
connector-name rule, not `default`, at least one connector, each configured), as
for a token. "No longer current" means the request's resource is not
`Resource(issuer)` or the server is off; and after `Disarm` nothing is claimed. There is no list of pending
authorizations: the console learns an id only from the browser that followed
the `302`.

## daemon

- **Building it.** `daemon.New` builds the server with
  `Server: func() config.Server` reading `configState.current().Server` (`New`
  has already called `cfgState.applying(cfg)`, so it is never nil while serving;
  a nil guard returns the zero `Server`, which is off), `Grants: tokens` (the
  `clientTokens`), `ApproveURL` returning
  `"http://" + cfg.Server.Listen + webui.ApprovePath + "?req=" + url.QueryEscape(id)`
  (the configured `server.listen`, the host `wayfindr ui` opens, so the
  console's cookie is sent), `Client: httpclient.PublicOnly()` (a nil
  `Client` falls back to it too), and the daemon clock's `Now`. It passes the four handlers in `httpd.Handlers` and
  `httpd.Config.ResourceMetadataURL`:
  `func() string { s := server(); if !s.OAuth.Enabled { return "" }; return oauthserver.ResourceMetadataURL(s.Issuer()) }`.
- **`clientTokens`** (`daemon/tokens.go`) implements `oauthserver.Grants` and
  stays `admin.ClientTokens`. Under its one mutex it now also keeps
  `resource`, the current `oauthserver.Resource(issuer)` (`""` while off),
  `clients`, the current `server.oauth.clients`, and `live`, the grant names
  it has put in the registry. A grant is **suspended** while
  `g.Resource != resource` or `g.ClientID` is not in `clients`.
  - `Create` (a client token) and `CreateGrant` share the name space; the
    store refuses a name either table has. `CreateGrant` refuses a name a
    client token could not have (not a connector name, or `default`) with an
    error wrapping `oauthserver.ErrInvalidName`.
  - `IssueGrantTokens` and `RotateGrantTokens` read the grant; `IssueGrantTokens`
    returns `store.ErrNotFound` when its `CreatedAt`, truncated to the
    millisecond, is not `created`'s (a grant re-created under the name),
    in the same check, under the same mutex, that finds it suspended. Both
    return `oauthserver.ErrSuspended` for a suspended grant, write the store, then
    `Registry.AddUntil` of the access digest with
    `clienttoken.Client{Name: g.Name, Connectors: g.Connectors, Remote: true}`
    until `*access.ExpiresAt`.
  - `RevokeGrant` deletes the grant, then `Registry.Remove(name)`. `Revoke`
    (admin, `wayfindr token revoke`) deletes the client token of that name, or
    else the grant of that name, then removes it from the registry; when
    neither exists it is `store.ErrNotFound`.
  - `ListGrants(ctx) ([]store.OAuthGrant, error)`, added to
    `admin.ClientTokens`.
  - `applyOAuth(ctx, s config.Server)` sets `resource` and `clients` from
    `s`; when either changed, it removes every `live` name from the registry,
    then, if on, adds back the unexpired access tokens
    (`ListOAuthAccessTokens`) of the grants that are not suspended. So turning
    OAuth off, changing `public_url`, or removing a client from `clients`
    stops those grants' access tokens at once, and undoing the change brings
    back the ones not yet expired. A store error is returned and leaves none
    added: it fails closed. It also sets `stale`, so that the next
    `applyOAuth` redoes the load even if the config did not change, and `run`
    retries the load on its touch timer (every minute, bounded by 10 s, for
    the `resource` and `clients` already set) until one succeeds; a failed
    retry is logged at warn.
  - `freeName(ctx, base string) (string, error)`: `base`, then `base-2` to
    `base-99`, the first taken by neither table.
  - The touch flush passes the registry's touches to both `TouchClientTokens`
    and `TouchOAuthGrants`. `run` also calls `PruneOAuth` at start and every
    hour, bounded by 10 s; a failure is logged and retried next hour. The
    hourly prune rides the touch timer: each tick checks whether an hour has
    passed since the last prune, so it runs within a minute of the hour.
- **Startup.** `daemon.New` calls `tokens.applyOAuth(ctx, cfg.Server)` right
  after it builds the token service from `loadClientTokens`, and before
  `httpd.NewServer`, so grants' access tokens work from the first request,
  as scoped tokens do. `applyOAuth` returns its store error, and that fails
  `New`, as `loadClientTokens`' does.
- **Reload.** `Reload` calls `tokens.applyOAuth(ctx, next.Server)` right after
  `cfgState.applying(next)`, before `Manager.Apply`, so a change that
  suspends grants applies before any connect waits. A store error there is
  logged at error; grants' access tokens stay refused until `run`'s retry
  succeeds. `Serve`'s startup apply calls it again and finds nothing changed.
  Right after, when the server turns on or off, its resource changes, or
  `server.oauth.clients` changes (`oauthChanged` of the current and next
  `[server]` tables), `Reload` calls `Server.Disarm`.
- **Admin wiring.** `admin.Options.OAuth` is an adapter over the server and
  `clientTokens`: `Arm` is `Server.Arm`; `Get` is `Claim` (which a reload,
  and the re-render after a refused approve, call again for the same id with
  no other effect) plus a suggested name, `freeName` of the first label of `ClientHost`, lowercased and cut to the
  connector-name rule (`oauth` if nothing is left or the host is an IP address;
  `chatgpt` for ChatGPT; empty when `freeName` finds all 99 taken);
  `Approve` and `Deny` call the server and map `ErrNoRequest` to an error
  wrapping `store.ErrNotFound`, `ErrContested` to one wrapping
  `admin.ErrContested`, and `ErrInvalidName` to one wrapping
  `admin.ErrInvalidApproval`. `daemon.Options.OAuthClient` replaces the

## httpd

```go
type Handlers struct {
	// … existing fields …

	// OAuthResourceMetadata serves GET /.well-known/oauth-protected-resource
	// and GET /.well-known/oauth-protected-resource/mcp.
	OAuthResourceMetadata http.Handler
	// OAuthServerMetadata serves GET /.well-known/oauth-authorization-server.
	OAuthServerMetadata http.Handler
	// OAuthAuthorize serves GET /oauth/authorize.
	OAuthAuthorize http.Handler
	// OAuthToken serves POST /oauth/token.
	OAuthToken http.Handler
}

type Config struct {
	// … existing fields …

	// ResourceMetadataURL returns the URL a remote /mcp request's 401 names
	// while Wayfindr's authorization server is on, and "" while it is off
	// (ADR 0022). Built from the canonical issuer, its host is the issuer's:
	// only a remote request whose Host is that host, or a loopback one with
	// a forwarding header, gets the public admission and the 401. host
	// calls it once per remote request, so a reload applies from the next
	// one. Nil means always off.
	ResourceMetadataURL func() string
}

// The authorization server's paths. httpd can't import oauthserver
// (design §2), so it names them itself; a daemon test
// (TestOAuthPathsAgree) asserts each equals oauthserver's constant.
const (
	ResourceMetadataPath = "/.well-known/oauth-protected-resource"
	ServerMetadataPath   = "/.well-known/oauth-authorization-server"
	AuthorizePath        = "/oauth/authorize"
	TokenPath            = "/oauth/token"
)
```

Routes added to the table, with a new guard flag `public`: no Origin check, no
bearer; it lets in a remote request that `host` admitted as public, and nothing
else lets one in. A local request always reaches them (the handlers answer 404
while off).

```
route                                         guards (after Host)   who passes
GET /.well-known/oauth-protected-resource     public                anyone local; remote only while on
GET /.well-known/oauth-protected-resource/mcp public                same
GET /.well-known/oauth-authorization-server   public                same
GET /oauth/authorize                          public                same
POST /oauth/token                             public                same
```

**The admission in the context.** The value `host` stores under `remoteKey`
becomes

```go
// admission is how host let a remote request in.
type admission struct {
	// client is the remote token's Client; zero for a public admission.
	client clienttoken.Client
	// public is an admission, with no token, to one of the authorization
	// server's routes.
	public bool
}
```

and `remoteFrom` returns it. `wrap` answers a remote request with the one 404
unless its route's guard matches its admission: `remote` for a token
admission, `public` for a public one. So a public admission never reaches
`/mcp`, `/ui/`, or `/admin/`, and a token admission never reaches a public
route.

`host`, for a remote request other than the callback, reads
`url := ResourceMetadataURL()` once, and treats it as `""` unless the request
came through the tunnel (`viaTunnel`): its `Host` is the issuer's host (the
host of `url`, which the canonical issuer built; compared case-insensitively,
a missing port taken as the issuer scheme's default), or its `Host` is a
loopback name with the daemon's port and it carries a forwarding header (a
tunnel that rewrites `Host`). A DNS-rebinding page's request, a foreign `Host`
and no forwarding header, is remote but not through the tunnel, so it gets the
404 on every public route and on `/mcp`, and can't read `public_url` from the
metadata or the challenge; so does a forwarding header beside a `Host` that is
neither. Then `host` resolves the bearer as today (`admitRemote`, on every
path, so a refusal does the same work), and:

1. admitted (a remote client token or a grant's access token on `/mcp`): on,
   as today, with `admission{client: c}`;
2. else, `url != ""` and the method and path are exactly one of the five
   routes above (`GET` on the four `GET` paths, `HEAD` too on the three
   metadata paths, `POST` on `TokenPath`): on, with `admission{public: true}`.
   A remote `HEAD /oauth/authorize` is not admitted and falls to step 4's
   404, so a link unfurler can't reach the authorize handler (which answers
   a local `HEAD` with 405 and keeps nothing pending);
3. else, `url != ""` and the path is `/mcp`: `401`, body `unauthorized`, with
   `WWW-Authenticate: Bearer resource_metadata="<url>"`, plus
   `, error="invalid_token"` when the request carried an `Authorization`
   header; logged at debug as `remote_token`, as every refusal is
   (`guards.reject`);
4. else: `404 page not found`, as today.

Step 2 matches the method as well as the path, so a remote request with
another method on a public path (`POST /oauth/authorize`, `GET /oauth/token`)
gets the same 404 as any refused remote request, never the mux's 405. The
path is compared exactly, so `/oauth/token/` or a path the mux would clean and
redirect is a 404 too.

Off, or not through the tunnel, steps 2 and 3 never run, so every answer is as
before. Step 1, the remote-token admission (ADR 0021), does not look at `Host`. A local `/mcp`
request is unchanged: a missing or wrong token gets 401 with exactly
`WWW-Authenticate: Bearer`, which the connection test relies on.

// ErrInvalidApproval is what Approve wraps for a name the server refuses
// although admin's own check let it through: the daemon turns
// oauthserver.ErrInvalidName into it, since admin cannot import oauthserver.
// The route answers it with 400.
var ErrInvalidApproval = errors.New("invalid approval")

// ErrContested is what OAuthRequests.Approve wraps when more than one
// authorization request arrived during the arm the request was claimed from
// (OAuthRequest.Arrived): one may be a stranger's, so none is approved. The
// daemon turns oauthserver.ErrContested into it. The route answers it with
// 409, and the request stays claimed for Deny.
var ErrContested = errors.New("contested authorization")

// OAuthRequests arms the authorization server and reads and answers its
// pending authorizations (ADR 0022). The daemon adapts oauthserver.Server
// to it; admin cannot import oauthserver (design §2).
type OAuthRequests interface {
	// Arm lets the next authorization through for 10 minutes and returns
	// when the arm ends (oauthserver.Server.Arm).
	Arm(ctx context.Context) (time.Time, error)
	// Get claims the pending authorization id (oauthserver.Server.Claim:
	// it consumes the arm and drops every other pending authorization;
	// the claimed id again has no other effect) and returns it with a free
	// grant name to suggest. An unknown, expired, answered, or unclaimable
	// id is an error wrapping store.ErrNotFound.
	Get(ctx context.Context, id string) (OAuthRequest, error)
	// Approve creates the grant and returns the URL the browser goes to
	// next. store.ErrNotFound as for Get, and for an id Get has not
	// claimed; store.ErrExists for a taken name, and the request stays
	// claimed; ErrContested, changing nothing, when the request's Arrived
	// is above one.
	Approve(ctx context.Context, id, name string, connectors []string) (redirect string, err error)
	// Deny ends the request and returns the URL the browser goes to next.
	Deny(ctx context.Context, id string) (redirect string, err error)
}

	ExpiresAt time.Time `json:"expires_at"`
	// Arrived is how many authorization requests became pending during
	// the arm this one was claimed from, this one included. Only one was
	// expected: above one, approve answers 409 and only deny is left.
	Arrived int `json:"arrived"`
}
