# §7.9 CLI

Part of the [Wayfindr technical design](../design.md). Go code cites this file
as "design §7.9".

Every command, flag, output, and exit code is in the public reference,
[CLI](https://atomicpages.github.io/wayfindr/reference/cli)
(`docs/reference/cli.md`). The CLI only parses flags and delegates: local files
(`init`, `connector add`/`edit`/`remove`/`import`'s config edit,
`connector list`, `scope`),
`daemonctl` (`start`, `stop`, `logs`), the shim (`stdio`), `service`,
`selfupdate` (`update`), or the admin API (everything else, through `admin.Client`). The root help groups the
commands (Daemon, Inspect, Manage, Plumbing); `newRootCmd` assigns the groups
in one place (`groupCommands`), not in each command's file. Notes on how they
do it:

- **`--json`** is one persistent flag on the root, not a flag per command. A
  command that prints data marks itself where it is built (`supportsJSON`, a
  cobra annotation) and reads the flag with `wantJSON`; the root's
  `PersistentPreRunE` refuses `--json` on any other command before it runs
  (`checkJSON`), so a script never takes text for JSON. The JSON shapes
  are the public contract in the CLI reference: snake_case, always-arrays,
  empty optionals omitted.
- **`--config` and `--data-dir`** are root persistent flags with no resolution
  of their own. `newRootCmd` overlays them on `Host.Env` (`pathFlags.overlay`)
  before it builds the commands, so `Getenv("WAYFINDR_CONFIG")` and
  `Getenv("WAYFINDR_DATA_DIR")` return them when set and every command resolves
  through `paths.Resolve` as before ([§3](3-paths.md)). The root's
  `PersistentPreRunE` makes relative values absolute against the working
  directory, since the daemon and service that receive them run elsewhere.
  `service install` writes the overlaid values into the unit, and a daemon
  `daemonctl.Ensure` starts gets its target's resolved paths (Spawn, below).
- **`config`** is a `runGroup` group. `config path` prints `paths.Resolve`'s
  two paths, existing or not. `config check` reads the file (`readConfigFile`,
  so a missing one says to run `init`) and runs `config.Parse` with the options
  the daemon loads it with, wrapping a failure as `config.Load` does
  (`load config <path>: …`); it never asks a daemon or opens the store or the
  keychain.
- **`auth`** is a group, `auth login` and `auth logout`, but not a plain
  `runGroup`: its old spellings stay, hidden. An argument that names no
  subcommand is a connector to log in to (`auth <connector>`), and `auth revoke`
  is a hidden copy of `logout`. So `auth` alone prints help, and a typo of a
  subcommand reaches the daemon as an unknown connector rather than failing
  with a suggestion.

- **`init`** is idempotent and never overwrites. It refuses to run while a
  daemon is listening ([§9](9-security.md)). Its report (`setup.WriteReport`)
  prints, per harness, a quick-connect command
  (`claude mcp add … -- wayfindr stdio`, `codex mcp add …`, …) or the entry to
  add to a config file, all over the shim, so none holds the client token; the
  HTTP setup is on the clients guide. It also names the clients
  `connector import` could read.
- **`start`** runs `daemonctl.Ensure`, which starts
  `wayfindr start --foreground` detached, logging to `<data>/wayfindr.log`, and
  returns once `/healthz` answers; `--foreground` runs the daemon in this
  process (`daemon.Run`), logging to stderr or `--log-file`. `serve` is the
  hidden old name of `start --foreground` (`serve -d` is `start`), kept for
  service files and scripts from before wayfindr-3e6f; it logs a deprecation
  warning (stderr only, so stdout stays clean). `stop` sends SIGTERM to
  the lock holder's pid and waits for the lock to drop; `logs` tails the daemon
  log (`daemonctl.Tail`).
- **`update`** (ADR 0023, `internal/cli/update.go`) needs no daemon.
  `selfupdate.Source` (`Host.Releases`; the zero value is GitHub) reads the
  latest tag from the `Location` of `/releases/latest` without following it, so
  there is no API rate limit and pre-releases and drafts are skipped as the
  installers skip them; a named version goes through `selfupdate.NormalizeTag`
  instead. `selfupdate.Compare` orders the running version (`Host.Version`, else
  the build's `version`) against it with `x/mod/semver`: a version whose base
  is not a full `vMAJOR.MINOR.PATCH` (`dev`, or a bare commit from
  `git describe --always`, even an all-digit one that semver alone reads as
  shorthand) is older than any release, and a `git describe` version
  (`v0.1.0-3-gabc123`) is its base tag plus commits, so newer than that tag. Without a named version only a newer
  release is installed; a named one is installed whenever it differs, and an
  older one gets a note linking the storage guide's downgrade caveat.
  `Fetch` downloads `selfupdate.AssetName(GOOS, HostArch(GOOS, GOARCH))`
  (`HostArch` picks arm64 under Rosetta, like `install.sh`) and `checksums.txt`,
  checks the SHA-256 before anything is written, and extracts only the binary.
  A transport error names the URL redirected to with `redact.URL`, since a
  release asset's carries a signed token in its query.
  `Replace` swaps it over `service.Executable()` (symlinks resolved;
  `Host.Executable` in tests), after removing `.wayfindr.*.new` temp files a
  killed run left: on Unix a same-directory temp file, chmod 0755, fsync, and
  rename; on Windows it deletes leftover `.old*` files, renames the
  running exe to `.old` (`.old-<rand>` if that one is still in use), then
  renames the new one in, as `install.ps1` does. Then, unless `--no-restart`
  or running as root through `sudo` (euid 0 with `SUDO_USER` set, where a
  restart would reach root's data directory and `gui/0`; it prints what to
  run as the user instead): `service.Restart` reloads an installed unit (the
  same `load` as install), because `KeepAlive {SuccessfulExit: false}` and
  `Restart=on-failure` never restart a clean exit, so a plain stop would leave
  the service down. Its `BeforeLoad` stops the lock holder first, the same
  `stopBeforeLoad` hook as `service install` (wayfindr-p9vn), or the unit's
  new daemon would find the old one running and exit 0. `Restart` reports
  false with no unit file or no service manager (Windows), and then
  `daemonctl.Stop` stops the lock holder (`ErrNotRunning` means there is
  nothing to restart), and the next shim's `daemonctl.Ensure` starts the new
  binary. A restart error after the swap says the binary was updated and gives
  the manual step (`wayfindr service install` or `wayfindr stop`). `--check`
  never downloads an archive, and `--json` is refused without it, since the
  install prints only text. Its suggested command names the version when one
  was named, since a plain `update` installs the latest.
- **`connector add`** checks the name and the file before probing the server for
  OAuth (`auth.Probe`), stores `--secret-header`/`--secret-env` values through
  the admin API, appends the table, and waits for the connector to settle
  (`admin.Client.WaitConnector`) unless `--no-wait`. `edit` and `import` wait
  the same way. When the daemon then reports a config error and `Status.Version`
  differs from the CLI's, it says the running daemon is another build and to
  restart it ([§7.7](7.7-httpd.md)). `remove` first prints its plan, from the
  file alone (so a credential or secret is deleted "if it is stored"), and asks
  through `confirmChange`, which `import` shares: `--yes` skips it, and off a
  terminal without `--yes` it fails before any change; `--dry-run` stops after
  the plan. Then it deletes the tables and, through the admin API (starting the
  daemon for it), the connector's credential and each secret only it
  referenced; a secret still in use is kept and named.
- **`call`** (`internal/cli/call.go`) runs one tool call through
  `POST /admin/tools/call` (`admin.Client.Call`), never through an MCP client of
  its own, so it and the console share the gateway's call core
  ([§7.6](7.6-gateway.md)). It first lists the connector's tools (`Tools`, 30s,
  as `connector tools`): a tool the connector doesn't serve fails there, and the
  entry gives the class for the question. A
  `write` or `destructive` tool that the tools list exposes asks through
  `confirmChange` (`--yes`; off a terminal it fails before the call); a hidden
  one is sent unasked, and the core refuses it. A listing the daemon refuses
  (an `*admin.APIError`, such as a connector not ready after a broken sign-in)
  doesn't stop the call: the class is unknown, so it asks as for a destructive
  tool, and the gateway's own error and the call-log row show why. A daemon
  that can't be reached still fails. `--token-file` (`-` is stdin)
  puts the trimmed value in the request body, never on the command line.
  The form prompts are pure functions over the JSON Schema (`call_schema.go`),
  whose properties come from `admin.SchemaFields`, which the console shares:
  properties in the schema's order (read with a token decoder, not a map). A
  number answer must be finite (JSON has no NaN or infinity). An
  `input_required` result is answered on stdin (one `bufio.Reader` for the
  whole round trip; a URL request waits for Enter and answers `accept`) and
  sent back with its `request_state`, at most 8 rounds; `--json` prints it and
  exits 0 instead, and a stdin already read for the arguments or the token
  fails. The preview is each content item's `admin.Content.Summary` (shared
  with the console) through `redact.Printable` line by line, cut at 4 KiB on a rune boundary; `--output` writes the wire result
  (0600). An `isError` result exits 1 through `exitWith`, since its text is
  already printed. `connector tools` (and `scope <connector>`, which shares
  `writeToolsTable`) prints `ToolEntry.RequiredArgs`. `connector tools
  <connector> <tool>` describes one tool's arguments (`argTable`: every type
  from `SchemaField.Types`, `Items` for arrays, descriptions on one line and
  wrapped to stdout's width only on a terminal), and with `--json` prints its
  `inputSchema`.
- **`connector import`** reads only the client's user-level files unless
  `--include-project` sets `clientconfig.Dirs.Project`: project files come with
  the repository, so a cloned repo chose their servers (wayfindr-awvh). Each
  existing one left unread is listed as `Not read`. The plan is printed through
  `redact.Printable`, since every value in it comes from someone else's file,
  and no server is asked anything until the plan is confirmed: `--dry-run`
  sends no request, and the OAuth probe (`askOAuth`) runs after the confirm,
  then the config edit is made again with the auth tables it found.

**Shim.** `wayfindr stdio` looks for the daemon (`daemonctl.Verify`, under
Daemon lock below). If the daemon isn't running, it
spawns a detached daemon (`wayfindr start --foreground`; `Setsid` on Unix,
`DETACHED_PROCESS` on Windows) and polls for 5s. It then runs an SDK
`mcp.Server` on stdin and stdout (`IOTransport`) that forwards `tools/list` and
`tools/call` to an SDK `mcp.Client` connected to `/mcp` with the bearer token.
Each hop negotiates its own protocol version, so the shim never parses raw
JSON-RPC beyond the message IDs it tracks for stdin EOF (below).

- **Headers.** Every request to the daemon carries `Wayfindr-Scope`, the project
  scope found from the shim's working directory ([§3](3-paths.md)), encoded by
  `Scope.Header`, and `Wayfindr-Profile` with `--profile`. A scope file that
  doesn't validate, or an invalid profile name, stops the shim: serving without
  it would give the project more than it asked for. Each `tools/call` also
  carries its client's `clientInfo` in `_meta`, so the call log names the
  harness rather than the shim.
- **Elicitation.** The shim's client declares elicitation (form and URL) and
  runs with the SDK's multi-round-trip handling off, so it sees the daemon's
  `input_required`. A stdio client at 2026-07-28 that can answer gets it as is.
  An older client is asked directly with `elicitation/create`, and the shim
  calls the daemon again with the answers and `requestState` until the daemon
  stops asking. A client that can't be asked gets an `isError` result saying so,
  after the shim tells the daemon, with `cancel` answers, that no one will
  answer.

- **Startup.** The shim reads the client token (`clienttoken.Read`) and
  `server.listen` (`config.ListenAddress`, below) before anything else, so a
  missing `init` fails at once. It connects before it serves: a daemon that
  won't start fails the shim on stderr, not on the first call.
- **Spawn.** `os.Executable() start --foreground`, inheriting the environment
  (so `WAYFINDR_*` overrides reach the daemon) with `WAYFINDR_CONFIG` and
  `WAYFINDR_DATA_DIR` set to the target's resolved config file and data
  directory (`Target.ConfigFile`, `Target.DataDir`, filled by `NewTarget`), so
  the daemon uses the starter's files whether they came from `--config` and
  `--data-dir`, the environment, or the defaults; stdin from the null device, and
  stdout and stderr appended to `<data>/wayfindr.log` (0600, its directory
  created 0700 if missing); the shim's own stdout carries only MCP, and its logs
  go to stderr. Unix: `Setsid`. Windows:
  `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`. The shim reaps the child if it
  exits while the shim runs. A child that exits while no daemon answers and none
  holds the lock fails the start at once ("the daemon exited before it
  answered"), rather than after the 5s timeout. `daemonctl.Ensure` does all of
  this, and `wayfindr start` uses it too.
- **Daemon lock.** `daemonctl.Verify` decides what answers on `server.listen`,
  and only the daemon it finds gets the client token (wayfindr-zvjw). It asks
  `/healthz`, then probes the daemon lock (`daemonlock.Probe`, a shared lock
  taken for a moment). `/healthz` comes first because a daemon takes the lock
  before it binds and drops it only after its server closes, so one that
  answered still holds the lock when it is read.
  - Held with the configured `server.listen` (or by a daemon that has not
    written itself in yet) and answering: the daemon.
  - Held but not answering: it is starting, so the shim polls without
    spawning.
  - Held with another `server.listen`: the config changed under a running
    daemon, so the shim fails with "daemon already running at `<old>` (pid N),
    but server.listen is now `<new>`: restart the daemon to apply it", rather
    than start a second daemon on the store.
  - Not held but answering: another program, or a daemon started with another
    data directory. The lock is in the user's 0700 data directory, so another
    user's process can't hold it. The shim fails with "something answers on
    `<listen>` but does not hold the daemon lock `<path>`" (`ErrNotOurs`),
    sends it nothing, and spawns no daemon to contend for the address.
  - Neither: it spawns.
  - A lock it can't read fails the shim: with no lock to check, nothing that
    answers can be trusted with the token.
  - The check runs on every new connection too (`Target.Transport`, whose
    `DialContext` calls `Verify`), not only before a session's first: the
    gateway is stateless, so after the daemon restarts the shim's session
    simply dials again, and the CLI's admin client does the same.
- **Races.** Two shims that both find no daemon both spawn one. The daemon takes
  the lock and binds before it opens the store ([§7.8](7.8-daemon.md)), so one
  wins and the other exits with "daemon already running" without touching the
  store. A child that exits while the lock is held lost that race, so the shim
  keeps polling `/healthz`; both shims then reach the winner.
- **Forwarding.** Results, `isError` ones included, pass through unchanged, and
  a JSON-RPC error the daemon answers with is passed on as one. A request that
  never reaches the daemon (the SDK marks it `ErrRejected`) or a broken session
  becomes an `isError` result suggesting `wayfindr status` (for `tools/list`,
  which has no `isError`, a JSON-RPC error with that advice). The session is
  then dropped, and the next request reconnects, starting the daemon again if it
  is gone.
- **Stdin EOF.** The SDK ends a session as soon as its reader hits EOF: it
  cancels the requests in flight and refuses to write their responses. So the
  shim puts `IOTransport` over its own stdin and stdout wrapper, which records
  the IDs of the requests it reads and of the responses written, and shows the
  SDK EOF only once every request has been answered (or stdout has failed, or
  the session is closed). A script that pipes requests in and closes stdin at
  once gets every answer, and the shim exits 0 (wayfindr-4qmt). A request the
  shim sends the client after EOF (`elicitation/create`) can never be answered,
  so the wrapper answers it with a JSON-RPC error, and the call gets the usual
  "could not be asked" result.
- **Capabilities.** The shim declares only `tools`, as the gateway does, and
  runs the same `toolsonly.Middleware` ([§7.6](7.6-gateway.md)): every
  `prompts/*`, `resources/*`, and `completion/*` request is -32601 at every
  protocol version, answered locally without a round trip to the daemon.

**Service.** `internal/service` writes a user-level unit that runs
`<binary> start --foreground --log-file <data>/wayfindr.log`, where `<binary>`
is `os.Executable()` with symlinks resolved. The launchctl or systemctl runner
is injected, so tests assert the commands and never run them.

Both units restart the daemon only on a failed exit, so a daemon that is not
the lock holder must not fail (wayfindr-p9vn):

- `start --foreground` exits 0 when `daemon.New` returns a
  `*daemonlock.HeldError`, as `wayfindr start` reports a running daemon. It
  logs the reason at info, or at warn when `refused` added the other
  `server.listen`. Without this, a unit whose daemon found another running
  (one a shim started in the service's restart gap, say) restarted for ever.
- `service install` (in `cli`, which keeps `service` a leaf) stops the daemon
  holding the lock with `daemonctl.Stop`, ignoring `ErrNotRunning`, and says
  so. It does it in `service.Options.BeforeLoad`, which `Install` runs once the
  unit is written and just before the load, so an OS with no service manager
  or a unit that can't be written stops nothing; a load that fails after the
  stop says the daemon is stopped and to run `wayfindr start`. The service's daemon then takes the lock with the unit's
  environment. Reinstalling over the service's own daemon is harmless: it exits
  0 on SIGTERM, which no unit restarts, and the load starts it again.
  `service.Restart`, which `update` calls, runs the same `BeforeLoad` (the
  `stopBeforeLoad` hook) once it finds the unit installed, for the same reason.

- **macOS.** A launchd agent with label `dev.wayfindr.daemon`, at
  `~/Library/LaunchAgents/dev.wayfindr.daemon.plist` (0644): `RunAtLoad`,
  `KeepAlive` `{SuccessfulExit: false}` (restart on failure only), and
  `StandardOutPath`/`StandardErrorPath` on the log file, which catches a daemon
  that fails before it opens `--log-file`. Install runs
  `launchctl print gui/<uid>/dev.wayfindr.daemon` and, if that succeeds (the
  agent is loaded), `launchctl bootout gui/<uid>/dev.wayfindr.daemon`; then
  `launchctl enable gui/<uid>/dev.wayfindr.daemon` (clears an earlier
  `launchctl disable`) and `launchctl bootstrap gui/<uid> <plist>`. Uninstall
  runs the same `print` and `bootout`, then deletes the plist.
- **Linux.** `$XDG_CONFIG_HOME/systemd/user/wayfindr.service`, else
  `~/.config/systemd/user/…`, with `Restart=on-failure`, `RestartSec=5`, and
  `WantedBy=default.target`; stdout and stderr stay with the journal. Install
  runs `systemctl --user daemon-reload`, `enable wayfindr.service`, and
  `restart wayfindr.service` (`enable --now` would leave a running daemon on the
  old unit). Uninstall runs `systemctl --user disable --now wayfindr.service`,
  deletes the unit, and runs `daemon-reload`.
- **Other OSes** fail with "service: not supported on <GOOS>: run
  `wayfindr start --foreground` under your own supervisor".
- **Idempotent.** Install always rewrites the unit and reloads it. Uninstall
  with no unit file runs nothing and says so.
- **Environment.** launchd and systemd start the daemon with their own
  environment, so the unit sets `PATH` (for stdio connectors' commands),
  `WAYFINDR_CONFIG`, `WAYFINDR_DATA_DIR`, `XDG_CONFIG_HOME`, and `XDG_DATA_HOME`
  from the installer's shell when they are set, so the daemon resolves the same
  paths ([§3](3-paths.md)); `--config` and `--data-dir` reach the unit as
  `WAYFINDR_CONFIG` and `WAYFINDR_DATA_DIR` through the overlaid `Host.Env`. `WAYFINDR_SECRET_KEY` and `WAYFINDR_CLIENT_TOKEN`
  hold secrets and are never written to a unit ([§9](9-security.md)); if they
  are set, install warns that the service won't see them, and the daemon uses
  the keychain or `master.key` and `client-token`. Variables the config reads
  through `${env:…}` don't reach the service either.
- **Log file.** Install creates the data directory (0700) and the log file
  (0600) if missing, so launchd appends to a 0600 file instead of creating a
  0644 one. An existing log is kept.

**Admin client.** Every command that talks to the admin API calls an
`admin.Client` method ([§7.7](7.7-httpd.md)) and never builds a path or a body.
`internal/cli/adminclient.go` only locates the daemon: `findDaemon(ctx, host)`
reads `server.listen` with `config.ListenAddress` and the bearer with
`clienttoken.Read`, checks the daemon with `daemonctl.Verify` (Daemon lock,
above), and only then builds the `admin.Client`, so the bearer and any secret
value go only to the daemon that holds the lock. No daemon, or a failed dial
later, means the daemon isn't running: the error wraps `errDaemonNotRunning`
and suggests `wayfindr start` or `wayfindr service install`, and the command
exits non-zero. A listener that does not hold the lock gets `Verify`'s error. A non-2xx response
is the Client's error, with the status and the daemon's message.

**Exit codes.** `RunWith` turns any error a command returns into exit code 1,
and cobra prints it as `Error: <message>`. A command that means another code
returns `exitWith(cmd, code)` (`internal/cli/exitcode.go`): an
`*exitCodeError` that `RunWith` finds with `errors.As`, with the command's
`SilenceErrors` set so no `Error:` line is printed, since the command has
already said what it means. `status --check` uses it for 2: a connector not
`ready`, a warning that isn't a note, or a config error. `update --check` uses
it for 2 when a newer release exists.

**Lenient listen-address read.** `config.ListenAddress`, shared by the admin
client and the shim, reads only `[server].listen`, so the CLI still finds the
daemon when the rest of the file is invalid: the daemon keeps its last good
config, and `wayfindr status` is how the user sees why. Unknown keys, wrong
types, and rule violations elsewhere are ignored, and an absent key is the
default `127.0.0.1:7777`. Its limits: it still fails on a TOML syntax error
anywhere in the file (a file that doesn't parse has no trustworthy `[server]`
table), on an unreadable file, and on a `server.listen` that is not a loopback
host:port. And it reads the file, not the running daemon: `server.*` needs a
restart ([§4](4-configuration.md)), so after an edit to `server.listen` the CLI
looks for the daemon at the new address until the daemon is restarted, and
reports it not running. The shim does not spawn a second daemon then: the daemon
lock ([§7.8](7.8-daemon.md) step 1) names the running one, and the shim reports
it with its address (Shim, above). `start --foreground` and the reload keep
`config.Load`'s full validation.

**`renderConnector`** is the one way the CLI writes a connector's state: the
advice's summary after the name, then its action and link indented, or "`<name>`
is ready." with no advice. `status`, `secret set`, `auth login`, and
`auth logout` use it, all over the same `admin.Connector` row.
