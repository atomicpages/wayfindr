# §7.7 `httpd`

Part of the [Wayfindr technical design](../design.md). Go code cites this file
as "design §7.7".

Every route, its methods, request and response bodies, and status codes are in
the public reference,
[HTTP Endpoints](https://atomicpages.github.io/wayfindr/reference/http)
(`docs/reference/http.md`). `httpd.New` (`internal/httpd/httpd.go`) registers
them with their guards:

- `GET /healthz`: loopback Host and Origin. Answers the version; `daemonctl`
  (for `start` and the shim) and the CLI probe it. An answer alone does not
  identify the daemon: `daemonctl.Verify` also requires the daemon lock
  ([§7.9](7.9-cli.md)).
- `POST`, `GET`, `DELETE /mcp`: loopback Host, Origin, bearer. The gateway;
  stateless, so GET and DELETE are 405. `?profile=<name>` picks a profile
  ([§7.6](7.6-gateway.md)); `Wayfindr-Scope` and `Wayfindr-Profile` are the
  shim's headers.
- `GET /auth/{connector}`: loopback Host and Origin. `POST /auth/{connector}`:
  loopback Host, same-origin `Origin`, and the form nonce ([§7.3](7.3-auth.md)).
- `/admin/`: loopback Host, Origin, bearer, default token only. `admin`'s own
  mux routes `GET /admin/status`, `GET /admin/secrets`, `PUT` and
  `DELETE /admin/secrets/{name}`, `POST /admin/auth/{connector}`,
  `GET /admin/auth/flows/{id}`, `DELETE /admin/credentials/{connector}`,
  `GET /admin/calls`, `POST /admin/search`, `GET /admin/tools/{connector}`,
  `POST /admin/tools/call` (a body of at most 4 MiB; its `token`, when set, is
  resolved by the daemon and never stored or logged), and
  `POST`, `GET /admin/tokens`, `DELETE /admin/tokens/{name}`,
  `POST /admin/ui/login`, `POST /admin/connectors`, `GET`,
  `PUT /admin/server/public-url`, `POST /admin/remote/test`, `GET`,
  `PUT /admin/server/oauth`, `POST /admin/oauth/arm`,
  `GET /admin/oauth/requests/{id}`, and
  `POST /admin/oauth/requests/{id}/approve` and `/deny`
  ([§7.11](7.11-oauthserver.md)).
- `GET /ui/`: loopback Host and Origin. `POST /ui/`: loopback Host, same-origin
  `Origin`. The web console (`Handlers.UI`, `webui.New`,
  [§7.10](7.10-webui.md)), which routes the tree itself and checks its own
  session cookie and CSRF token.
- `GET <auth.CallbackPath>` (`/oauth/callback`): any Host, no Origin check; its
  `state` is its guard.
- Wayfindr's authorization server (ADR 0022, [§7.11](7.11-oauthserver.md)),
  five routes behind the `public` guard (no Origin check, no bearer):
  - `GET /.well-known/oauth-protected-resource`
    (`Handlers.OAuthResourceMetadata`);
  - `GET /.well-known/oauth-protected-resource/mcp` (the same handler);
  - `GET /.well-known/oauth-authorization-server`
    (`Handlers.OAuthServerMetadata`);
  - `GET /oauth/authorize` (`Handlers.OAuthAuthorize`);
  - `POST /oauth/token` (`Handlers.OAuthToken`).

  A local request always reaches them, and the handlers answer 404 while
  `[server.oauth]` is off. A remote request reaches them only while it is on
  (`Config.ResourceMetadataURL` returns a URL), only through the tunnel (see
  Loopback Host below), and only with the route's own method: any other method
  gets the uniform 404, never a 405. httpd can't
  import `oauthserver` (§2), so it declares the four paths itself
  (`httpd.ResourceMetadataPath`, `ServerMetadataPath`, `AuthorizePath`,
  `TokenPath`), and a daemon test, `TestOAuthPathsAgree`, asserts each equals
  `oauthserver`'s constant of the same name. The route table's entries for them and the
  methods `host` admits come from one list (`publicRoutes`). `NewHandler`
  refuses a `CallbackPath` that equals or sits under any other route's path
  (`/mcp`, `/healthz`, `/auth/`, `/admin/`, `/ui/`, or one of the four).

- **Loopback Host** means a `Host` of `127.0.0.1`, `localhost`, `[::1]`, or the
  IP literal the listener is bound to (`httpd.Config.IP`, which `NewServer`
  fills, so `listen = "127.0.0.2:7777"` is reachable by its own address; an IP
  literal can't be rebound), with the configured port, on a request with no
  forwarding header (`Forwarded`, `Via`, `X-Forwarded-For`, `-Host`, `-Proto`,
  `X-Real-IP`, `CF-Connecting-IP`): a tunnel can rewrite `Host` to loopback but
  adds one of these (wayfindr-rrvq). Any other request is remote: it is accepted
  on `/oauth/callback` (ADR 0007), and on `/mcp` if and only if its bearer
  resolves to a remote scoped token (ADR 0021; an OAuth grant's access token
  resolves to one), and gets 404 everywhere else. While `[server.oauth]` is on
  (ADR 0022) and the request came through the tunnel, it is also accepted,
  with no token, on the five authorization server routes, and a remote `/mcp`
  request without a valid remote token gets 401 with
  `WWW-Authenticate: Bearer resource_metadata="<url>"` (plus
  `, error="invalid_token"` when it carried an `Authorization` header) instead
  of 404; the URL is `Config.ResourceMetadataURL()`, read once per remote
  request, so a reload applies from the next one. **Through the tunnel**
  (`viaTunnel`) means the `Host` is the issuer's host (the URL's host, which
  the canonical issuer built; compared case-insensitively, a missing port as
  the issuer scheme's default), or a loopback name with the daemon's port on a
  request with a forwarding header (a tunnel that rewrites `Host`). Any other
  remote request, such as a DNS-rebinding page's (a foreign `Host`, no
  forwarding header) or one with a forwarding header beside a foreign `Host`,
  gets the 404 on those routes and on `/mcp` without a remote token, so it
  can't read `public_url` from the metadata or the challenge. The remote-token
  admission to `/mcp` does not look at `Host`. The context holds how a
  remote request was let in (`admission`: a token's Client, or public), and
  each route's guard admits only its own kind (`remote` or `public`); any
  other route answers 404.
  The host guard makes that whole decision before routing (`admitRemote`): it
  resolves the bearer on every remote request, whatever the path, so every
  refusal is the same 404 for the same work, then puts the Client in the
  context, where the `/mcp` routes' bearer guard takes it instead of resolving
  again, and any other route answers 404. Origin, the connector limit, and the
  method still apply as for a local request. The path is
  `auth.CallbackPath`, which `daemon` passes in `httpd.Config.CallbackPath`;
  `httpd` keeps the route and the guard but not the path.
- **Origin.** On every route but the callback and the authorization server's
  five (`/healthz`, `/mcp`, both `/auth/{connector}` methods, and all of
  `/admin/` and `/ui/`), a request with
  an `Origin` header that isn't loopback (`http` or `https` on `127.0.0.1`,
  `localhost`, `[::1]`, or the bound IP, any port), or with more than one,
  gets 403. Requests without `Origin` (CLI tools) are allowed.
  `POST /auth/{connector}` and every `POST /ui/` also require exactly
  `Origin: http://<Host>`. A page whose `Referrer-Policy` is `no-referrer` makes
  the browser send `Origin: null` on its form posts, which this refuses. The
  callback has neither a Host nor an Origin guard (ADR 0007); its `state` is its
  guard.
- **Bearer** (ADR 0012). The guard requires exactly one `Authorization: Bearer`
  header and resolves it to a `clienttoken.Client`: the default token, compared
  in constant time, is `Client{default, nil}` (every connector); otherwise the
  SHA-256 digest is looked up in the `clienttoken.Registry`, which records a
  touch, and a hit is `Client{name, connectors}` (an entry added with
  `AddUntil`, an OAuth grant's access token, misses once it expires); anything
  else is 401 with `WWW-Authenticate: Bearer`. The guard stays the authority: it
  applies the one-header rule and logs refusals. `/admin/` uses it with
  `adminOnly`: the default token passes, a valid scoped token gets 403
  `This client token cannot use the admin API.`, and anything else 401. `/mcp`
  chains the go-sdk's `auth.RequireBearerToken` (with `AllowMissingExpiration`)
  after the guard, only to carry the Client into `req.Extra.TokenInfo`, since
  the SDK's context key is unexported. Its verifier returns the Client the guard
  already resolved, so a token is never resolved twice, as `Client.TokenInfo()`.
  The gateway serves MCP statelessly (`StreamableHTTPOptions.Stateless`), so no
  session outlives a request and each request is narrowed by its own token. The
  gateway's `clientOf` reads it once per request with
  `clienttoken.FromTokenInfo`; the result feeds both `narrowingOf`, which
  refuses a request that carries none, and the call log's token name. The
  registry is a digest → Client map behind a mutex, holding only `Scoped()`
  clients: it ignores one with no connector limit or named `default`, so a hit
  is never the default token, and `adminOnly` refuses exactly the clients that
  are `Scoped()`. The daemon loads every `client_tokens` row into it before
  httpd serves ([§7.8](7.8-daemon.md) step 9); admin's token routes update the
  store and the registry together, so a revoke applies from the next request on.
  The daemon drains the registry's touches, keyed by digest, into
  `TouchClientTokens` (and `TouchOAuthGrants`) once a minute and at shutdown.
- **Timeouts.** Set only `ReadHeaderTimeout` (10s) on the `http.Server`. No
  `WriteTimeout` or `IdleTimeout`: 2026-07-28 clients such as Claude Code hold a
  long-lived `subscriptions/listen` POST stream open on `/mcp`, and those
  timeouts would cut it (spike `wayfindr-91t`). Upstream call deadlines come
  from the connector `timeout` through the request context.
- **Server lifecycle.** `httpd.Server` owns the hard stop. Every request's
  context derives from one base context (`http.Server.BaseContext`).
  `Shutdown(ctx, grace)` stops accepting connections and drains in-flight
  requests until `ctx` ends. Requests still running then, such as a long-lived
  stream, are cancelled through the base context, and Shutdown waits up to
  `grace` more for them to return. Every request context is cancelled once it
  returns, and it returns an error only if requests are still running after the
  grace. The daemon passes the 10s drain and a 1s grace ([§7.8](7.8-daemon.md)
  step 4).
- **Why `/auth/{connector}` asks for confirmation.** A plain GET that started a
  flow would let any web page push the user into an unexpected consent screen.
  The confirmation page and its same-origin POST prevent that.
- **The admin API** lives in `internal/admin`, not here. `admin.New(Options)`
  returns one `http.Handler` that routes every `/admin/*` path on its own stdlib
  `http.ServeMux` (method and path patterns, `r.PathValue`; an unknown path is
  404 and a wrong method 405), and `httpd` mounts it once at `/admin/` behind
  loopback Host, Origin, and bearer (`httpd.Handlers.Admin`). `admin.Options`
  holds the dependencies, built once by `daemon`: the manager's `Status` and the
  recovery module's `SecretChanged` (`Upstreams`), the store, the secret writer,
  deleter, and lister (`PutSecret`, the resolver's; `DeleteSecret` and
  `ListSecrets`, the store's; nil answers 501), the daemon's `Version`, the
  config view (`Config`: configured names, profiles, the last reload error, and
  what refers to each secret), the auth flows (`Flows`), the revoke
  (`Credentials`), the credential health (`Health`: token expiry and warnings),
  the call log's retention (`CallRetention`), the console's login codes
  (`UILogin`, `webui.Sessions.IssueLogin` adapted; nil answers 501), the
  connector writer (`AddConnector`, the daemon's `configWriter`; a refusal is an
  `*admin.ConfigError{Kind, Case, Advice}`, answered with the status its Kind
  gives (400 invalid, else 409) and advice; nil answers 501), the gateway's
  search (`Search`, a function, since `admin` cannot import `gateway`; a refused
  search is an `admin.SearchError` carrying the gateway's Kind, Case, and
  advice), the tool lister (`Tools`: `Manager.PeekTools` with each tool's class
  and whether the tools list exposes it), the scoped tokens (`Tokens`; nil
  answers 501), the authorization server's pending authorizations (`OAuth`, an
  `admin.OAuthRequests` the daemon adapts; nil answers 501), the
  `[server.oauth]` writer (`SetOAuthEnabled`; nil answers 501), the user ID, and
  the logger. Request bodies are read with a size cap and a strict decode
  (unknown fields and trailing data are 400). The browser auth routes
  (`/auth/{c}`, `/oauth/callback`) are not admin routes and stay separate
  `httpd.Handlers` fields with their own guards (form nonce, state).
- **`admin.Client`** (`admin.NewClient(baseURL, token, httpClient)`) has one
  method per endpoint (`Status`, `PutSecret`, `DeleteSecret`, `ListSecrets`,
  `StartAuth`,
  `WaitAuth`, `Revoke`, `Calls`, `Search`, `Tools`, `CreateToken`, `ListTokens`,
  `RevokeToken`, `UILogin`, `AddConnector`, and the OAuth ones of
  [§7.11](7.11-oauthserver.md)), plus `WaitConnector`, which polls
  `Status` until a connector settles (`connector add`, `edit`, `import`). An
  endpoint is one route in `admin.New`, its handler, and its Client method,
  tested by a round trip of the real Client against the real handler; a new
  dependency also touches `daemon`'s wiring. A non-2xx response is an
  `*admin.APIError{Method, Path, Status, Message}` whose text is the daemon's
  message alone; a transport error is wrapped, so the caller can tell a failed
  dial. `admin.NewLocalClient(h)` is a Client whose transport calls `h` in
  process (no socket, no bearer); the web console reads through it
  ([§7.10](7.10-webui.md)).
- **`admin.Status`** is the JSON contract `wayfindr status --json` prints
  unchanged. Each connector is an `admin.Connector`, the one row type every
  admin response that reports a connector uses (the secret set's `retried`, the
  auth flow's and the revoke's `result`). Connectors come from `Manager.Status`,
  sorted by name; `advice` is `ConnectorStatus.Advice()`
  ([§7.2](7.2-upstream.md)), absent once `ready`. Upstream's vocabulary (`kind`,
  `case`, `ref`) and the technical `reason` stay out: a user reads `advice`, and
  the daemon log has the rest. `tools` is `Store.ToolCounts`, `hidden_tools` the
  last sync's hidden list, `last_sync` `Store.LastSync`, `token_expires_at` and
  `warnings` from `Options.Health` (absent when the token is bound to the old
  `url`, since it will never be sent). `Status.Version` is the daemon's build
  version: the CLI compares it with its own, and when `connector add`, `edit`,
  or `import` leaves the daemon on a config error, says the running daemon is
  another build (`staleDaemon`; an empty version means one from before the
  field) and to restart it, since an older daemon rejects keys it doesn't know.
- **Secrets.** `PUT /admin/secrets/{name}` checks the `${secret:name}` grammar
  ([§4](4-configuration.md)) and a non-empty value under a 64 KiB body, stores
  it through `PutSecret`, then calls `Upstreams.SecretChanged(name)`, which the
  recovery module serves ([§7.8](7.8-daemon.md) step 5): the connectors waiting
  on that secret retry, and the answer lists them, as rows, once each has
  settled and synced; admin never reads `Kind` or `Ref` itself. Once the value
  is stored the set has succeeded, even if a row's store reads fail.
  `DELETE /admin/secrets/{name}` removes it (404 when there is none) and
  reconnects nothing. `GET /admin/secrets` (`secret list`) answers
  `{"secrets": [{"name", "used_by"}]}`: the names `ListSecrets` reads, sorted,
  never a value, each with what in the running config refers to it.
  `used_by` comes from `ConfigState.SecretUsers`, which the daemon builds once
  per applied config with `config.Config.SecretUsers` (the same
  `Connector.Secrets` and `Embedding.Secrets` that `connector remove` and the
  embedder's secret set use): `connectors.<name>` and `embedding.api_key`,
  sorted, and an empty array when nothing refers to it. A secret referred to
  but not stored is not listed; status shows the connector waiting on it.
  Neither the value nor the body is ever logged ([§9](9-security.md)).
- **Auth flows.** `POST /admin/auth/{connector}` reaches `auth.Flows` through
  `admin.Flows`, which the daemon adapts, converting types only: auth looks the
  connector up, checks OAuth, and decides the status and advice
  (`auth.HTTPStatus`), so the browser's pages answer the same. A flow that
  cannot start is an `*admin.FlowError{Status, Kind, Case, Advice}`.
  `GET /admin/auth/flows/{id}?wait=` long-polls (at most 60s); a flow reads
  `done` only once the reconnect its token started has settled
  ([§7.8](7.8-daemon.md) step 5), so its `result` row has the tools.
- **Tokens.** `POST /admin/tokens` checks the name rule, that it isn't
  `default`, and that every connector is configured, then stores the digest and
  adds it to the registry; the value is in that response only and never logged.
  A name an OAuth grant has is taken too. `GET /admin/tokens` lists OAuth
  grants next to scoped tokens, with `kind` and `client`. Revoking deletes the
  row, of either kind, then the registry entry
  ([§7.11](7.11-oauthserver.md)).
- **Revoke.** `DELETE /admin/credentials/{connector}` answers once the recovery
  the revoke started has settled ([§7.8](7.8-daemon.md) step 5); the row is
  absent for an orphaned credential, and no credential is 404.
